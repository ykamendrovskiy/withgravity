# verify

Обычный путь гейта — `harness/HARNESS.md` (справочник полей/exit-кодов/установки — `harness/HARNESS-REFERENCE.md`, адресно). Три режима — по контексту вызова.

## После сборки (из build или «собери и проверь»)
1. Проект → `acceptance-plan.json` (нет → `complete: false`, так и скажи); `scenarios.manifest.json` — гейт обойдёт состояния.
2. `VITE_SCENARIOS=1 npm run build`, предпросмотр на временном порту, `node <скилл>/harness/run-gate.mjs <url> <проект> <проект>/gate-out`.
3. Вердикт — четыре признака: `valid` (проверка состоялась) · `complete` (что пропущено, почему) · `summary` (находки) · `checks`
   (по плану: гейт пересчитывает применимость сам; `fact_mismatch` — признак в плане записан неверно, находка о плане;
   `needs_clarification` — unknown; каждая проверка — execution done / not-run с причиной).
4. **not-run с `needs_human`** — измеримое выполни сам скриптом (Playwright из гейта) и запиши evidence: метод · исполнитель
   (гейт / агент-скрипт / человек) · область · ревизия · замер; result pass / fail / inconclusive — **в `gate-out/evidence.json`** (объект `{schemaVersion, items[]}`), одна
   запись на проверку, `revision` — sha сборки; AUDIT.md и сводка для человека строятся из вердикта + evidence (единая сводка, не пересказ). Суждение, требующее
   человека, остаётся открытым. `no_implementation` / `no_scenarios_manifest` — честно not-run.
5. Находки чини классами по записям (`../../resources/conventions.json`, `snippets/`, `traps/`), максимум 2 итерации, re-gate.
   Известное ограничение (`known`) — не твоя находка и не «чисто»: строкой «известные ограничения: N».
6. Свежий взгляд по скриншотам (полный режим): один суб-агент на все скриншоты с вопросом «что странного / сломанного / против
   конвенций; ЧТО — ГДЕ — ПОЧЕМУ, серьёзные первыми, не выдумывать»; триаж — подтверждается замером → находка, затем класс: дефект сборки /
   известное ограничение библиотеки / предпочтение; **штатность элемента ДС — не основание отбросить** (ошибка интеграции, темы или самой
   библиотеки остаётся находкой); не подтверждено замером → в отчёт как наблюдение, не чинить.

## Standalone-аудит (чужой проект)
То же, но без правок: находки + рекомендации. Нет плана — «проверки по конвенциям не оценены», не «чисто».

## Сравнить копию (шаблоны)
Три стороны: база (по записи использования `TemplateUse`, иначе git-история источника) · текущий потребитель · новая версия
источника. `mode: copy` — что адаптация (записана ли), что upstream, где пересекаются (конфликт — решает человек); `mode: import` —
совместимость с разрешённой версией и контрактом. Слияния нет; правки — только по просьбе. Гейт — если изменение могло сломать рендер.

## Отчёт — два блока
`gate-out/AUDIT.md`: **находки** (что · где · класс · как чинить · замер с шириной) отдельно от **покрытия** (done / not-run с
причинами, известные ограничения, что в плане неверно). В чат — коротко: что проверено и насколько полно; пункты — одно
предложение + дизайн-причина в скобках; без замеров и имён кода (они в AUDIT.md); «могу починить любой пункт — скажи номера».

## Не делать
Не править `harness/`; не подгонять код под чек; static-only не выдавать за полную проверку; не занимать порт пользователя;
впечатление не чинить как находку; `done` гейта не значит pass — читай result и evidence.

Граница официального скилла: его проверка заканчивается на typecheck — раскладку, контраст и состояния он не видит; это закрывает гейт здесь (политика withgravity, не ошибка официального).
