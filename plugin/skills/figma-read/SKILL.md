> Экспериментально: проверяется на внутренних библиотеках команды (паспорта `libraries/figma/<id>/` пакета: `inventory.json` + `binding.json` с ключами); без пакета — только то, что отдаёт Figma MCP. Успех основного цикла build на это не переносится.
# figma-read → спецификация
Требует Figma MCP (чтение). Протокол чтения по секциям, карта имён кита → код, политика фиделити («макет = что строить,
плагин = как») — `mapping.md` рядом. Выход — файл по `../../resources/spec.md`: `source` с ревизией и границей прочитанного;
`areas`, `components` (library-id, ключ/node-id, кодовое соответствие, варианты; неизвестное — `unresolved`), `theme`,
`behavior` с пометками observed / requested / inferred / unknown (статичный макет не доказывает поведение), `facts` по
`../../resources/facts.md`, `conflicts` с профилем. Читает профиль и тему проекта, чтобы знать, что уже есть.
Спрашивает один раз и только при расхождении макета с профилем (тема, плотность, словарь): три исхода — по макету одноразово
(override) · сохранить профиль, отклониться от макета · обновить профиль (через `profile`, затем спецификация ссылается на
новую ревизию). Совпадает — не спрашивает. Нет профиля → предложить снять его с макета (`profile`, экспериментально).
Повторяющиеся фреймы → кандидат в шаблон в `proposals.json`.
