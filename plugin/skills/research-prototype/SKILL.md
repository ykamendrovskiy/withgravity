# research-prototype

## Вход
`scenarios.manifest.json` (если есть), карточка экрана, каталог `../../resources/states.json`, принятые в build состояния и решение
о панели. Объём исследовательских состояний выбирает человек: предложи чек-листом применимые по признакам (`../../resources/facts.md`).

## Делает
1. Манифест по `../../resources/scenarios.md`: каждый сценарий — путь (пресет данных · начальное состояние · действия · ожидаемые
   переходы · сброс), не снимок, в который реальный поток не попадает.
2. Панель прототипа по тому же файлу: видна сразу в dev и scenario-сборке, deep link `?scenario=`, тема в URL, сброс без перезагрузки,
   шорткат, режим респондента по запросу.
3. Состояние, недостижимое реальным потоком (только подменой), — предложи добавить обработку в код.

## Выход
Манифест + панель; ссылка на стартовый сценарий и шорткат — в сдачу build. Проверка состояний — `../verify/SKILL.md` по манифесту.
