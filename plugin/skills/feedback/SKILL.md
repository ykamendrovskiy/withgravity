# feedback

Захват, не диагноз: запись дословно со слов тестера, класс — подсказкой, не вердиктом.

1. Окружение сними сам: версия плагина (`plugin.json`), версии `@gravity-ui/*` (`package.json` проекта), путь к коду.
2. По одному пункту на проблему: severity (blocker / major / minor / nit) · что · где · ожидал / получил · repro (шаги или
   сниппет + файл); нет воспроизведения — «не воспроизвёл — нужна репродукция», механизм не сочинять.
3. Покажи запись; предложи маршрут по классу: дефект реализации → `build` (local-fix); правило сервиса / «так задумано» →
   `profile` (как pending в `proposals.json`); ошибка официального скилла → строка в `errata-official-skill.md` с условием
   удаления; уже записано → подтверждение. Сам в профиль/шаблоны не пишет.
4. Наружу (публичный issue) — только по явной просьбе и после предупреждения убрать внутренние имена и URL.
