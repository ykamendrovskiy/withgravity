# Как применять профиль сервиса
`service-profile.json` (схема рядом, валидатор `validate.mjs`) задаёт «как принято в этом сервисе». Нет профиля — собирай по
официальному скиллу и общим конвенциям, в отчёте одна строка.
- Профиль **уточняет открытые ручки** (плотность, раскладка и max-width контента, форм-политика, тема); омиссия = дефолт гайда.
- Профиль **не отменяет корректность**: имена, версии, обвязка — официальный скилл и конвенции плагина; конфликт → корректность, пометка.
- `approvedComponents`: `deny` — не использовать; `preferred` — решает развилки «it depends».
- Тема: `theme.themeConfig.css` → скопировать в проект, импортировать **после** `styles.css`; `brandTokens` → полный набор на обе темы;
  токены руками не подбирать.
- Шаблоны: `templates[]` (прежнее `archetypes[]` — алиас; конфликт двух полей — ошибка); прежний формат пакета `blocks/` + `archetypes/`
  с `index.md`/`card.md` читается как шаблоны. `libraries` — внутренние пакеты и Figma-библиотеки сервиса (экспериментально).
- Конфликт профиля с кодом: сначала установить, что устарело; отклонение задачи — в запись использования шаблона/спецификацию.
- Образец в `examples/` показывает формат, не канон дизайна.
